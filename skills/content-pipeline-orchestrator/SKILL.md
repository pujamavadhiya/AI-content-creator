B. Orchestrator
name: content-pipeline-orchestrator
description: Entry point for all content requests. Use when a user asks to write, plan, rewrite, optimize, or repurpose any content and the right sequence of skills isn't obvious. Routes the request through keyword research, SERP analysis, brief, drafting, fact check, QA, SEO packaging, and export.
Purpose
Decide which skills to run, in what order, and what to ask the user. Prevent the user from having to know the skill names.
Step 1. Classify the request
Request type
Pipeline
Write something new, topic only
Keyword Research, SERP Gap, Brief, Draft, Fact Check, QA, SEO Package
Write something new, outline supplied
Draft, Fact Check, QA, SEO Package
Rewrite a live page
Rewrite With URL, Fact Check, QA, SEO Package
Update an old post
Content Refresh Audit, then Rewrite or Draft
Plan a month of content
Topic Cluster Planner, then Briefs
Turn one piece into many
Repurposing
Short copy (ads, emails, product text)
Format Playbooks, Headline Lab, QA
Translate or localize
Localization, QA
Step 2. Collect inputs once
Ask for missing items in a single message, never one at a time: topic or keyword, content type, audience, goal, word count, language, and whether a brand voice or author profile exists. Use sensible defaults for anything the user skips and state them.
Step 3. Run the pipeline
Announce the plan in one line. Run each skill in order and pass outputs forward. Don't re-ask for information a previous step already holds.
Step 4. Deliver
Return the final content first, then a short checklist: sources used, claims that need the user's verification, schema and meta ready, and suggested next step. Export to the format requested (chat, docx, markdown, html).
Rules
	•	Never skip Fact Check for content containing numbers, quotes, medical, legal, or financial claims.
	•	If the user says "just write it", compress the pipeline but keep Fact Check and QA.
	•	Keep the user informed in one line per stage, not paragraphs.
